| 同上 | `WindSpeedTask()`、`MotorControlTask()` | 只融合有效且未过期的两路输入，记录融合所用样本时间。电机任务统一执行正常启停、PWM、PID；自动模式数据失效时停机，恢复后重新启动自动流程。 |
| 同上 | `AntiBackflowTask()` | 未激活且浓度 ≥100 时激活；激活后浓度 ≥50 保持，＜50 解除。只更新请求，不操作电机；失效或退出模式清除激活状态，恢复后重新按 100 判断。 |
| 同上 | `System_SwitchMode()`、`System_ToggleMotor()`、`System_SwitchSpeedLevel()` | 持锁更新模式/档位请求，持锁后再次检查 OTA 与启动许可。进入和退出模式时复位计时、防回流状态及 PID 复位请求。 |
| 同上 | `UIDisplayTask()`、`System_GetState()`、`SpeedCalcTask()` | UI 在短暂持锁时复制状态及自动子状态，解锁后显示。状态获取接口改为向调用者缓冲区复制快照；测速结果在锁内发布。 |
| 同上 | `App_SelfTest()`、`IapPlatform_Enter()` | 自检改为持锁读取 DHT11 的当前有效状态，保留原有健康轮次、Flash/镜像检查及转正流程；MQ2 故障不新增整机启动失败条件。OTA 仍可立即停机，同时复位模式请求。 |
| `tools/host_tests/run_control_selftest.py`、`test_control.c` | 主机回归测试 | 从当前源码提取原样任务/驱动函数进行编译，直接链接风速及 PID 实现；仅模拟 RTOS、ADC、DHT11、LCD、电机寄存器与 Flash 接口。 |

## 控制与并发规则

- 调度开始后，系统状态、自动模式子状态、融合样本时间和 PID 复位请求均使用 `g_dataMutex`。系统初始化在调度器启动前完成。共享状态不再以可写指针对外暴露，外部读取使用 `System_GetState(&snapshot)`；本仓库没有旧接口调用者。
- 正常电机输出由 `MotorControlTask` 每 50 ms 执行。按键请求最迟在下个电机周期生效；防回流以原有 100 ms 周期判断。故障复位与 OTA 保留直接安全停机。
- 仅有限的内存运算、浮点计算及电机寄存器写入在锁内执行；LCD、DHT11、MQ2、Flash 操作均不持状态锁。
- 温湿度失败时，MQ2 继续采集，使用有效气体数据的防回流仍可运行。MQ2 失败时，温湿度继续采集，自动/防回流停止；手动模式仍可工作。
- 失败值保留最后一次数值供诊断，但有效标志为 0，不参与控制。既检查最新样本年龄，也检查融合结果所用样本年龄，避免风速任务滞后时继续使用过期 PWM。
- 成功的新采样不会使自动电机每 500 ms 停顿一次；尚未过期的上一份有效融合结果可以继续使用，直到下一次风速计算。
- 启动仍要求原有 DHT11 健康条件；启动期间 DHT11 持续失败会沿用原有自检失败/回滚路径。运行期间两路故障各自隔离。

## 可执行验证

在工程根目录运行（需要 Python 3、GCC；Keil 脚本默认使用本机已安装的 ARMCC）：

```powershell
python -X utf8 tools/host_tests/run_control_selftest.py
python -X utf8 tools/host_tests/run_iap_selftest.py
.\tools\build_keil.ps1
```

控制测试使用 `-Wall -Wextra -Werror` 编译，以下 7 组测试全部通过：

1. 温度、湿度逐整数步进时归一化值严格递增；下限/上限限幅、权重及 PWM 映射。三路归一化均为 0.4 时 PWM 为 52%，CCR 为 520。
2. DHT11 失败时仍完成 10 次 MQ2 采样并更新；MQ2 超时时 DHT11 仍更新；零 ADC、满量程 ADC、恢复及新采样无停机脉冲。
3. 1500/1501 ms 有效期边界、旧融合结果过期、恢复和 tick 回绕。
4. 49/50/99/100/2000/10000 浓度序列、迟滞、气体过期和两次任务周期之间快速退出/重入防回流。
5. 待机/手动/自动/防回流、PID 档位、状态快照、LCD 解锁显示、按键等锁期间 OTA 抢占，以及电机周期后 OTA 立即停机。
6. 自动模式启动、烹饪、延时关机状态迁移，原有 60 s/60 s/10 s 计时边界。
7. 自检保留 DHT11 有效期、健康轮次、Flash/镜像检查；MQ2 失效不连带阻止原有健康检查。

原有升级测试全部通过：正常安装 252 个、恢复 94 个，共 346 个模拟断电检查点；回滚、认证、元数据、协议解析及 Python 上位机丢失 BEGIN/DATA/END ACK 重试均通过。

## 边界及实板验证（未执行）

本次没有连接开发板。主机测试的任务交错由模拟调度注入，不能证明真实中断时序、DHT11 电气时序、ADC 电压校准、电机响应或运行时栈水位。

1. 正常启动后观察状态有效标志、采样时间及 PWM；缓慢改变温湿度，确认 PWM 随各个采样档连续变化，权重/限幅不变。
2. 正常运行后断开 DHT11 数据线，确认 `dhtValid=0`，MQ2 浓度及时间戳继续更新，自动停机；恢复 DHT11 后确认重新有效。测试应在启动自检成功后进行，以区别原有启动健康门槛。
3. 在受控 ADC 故障注入条件下测试 MQ2 超时或零读数，确认 `gasValid=0`、温湿度继续更新、自动和防回流停机。模拟量线路断开可能悬空，软件不能保证识别所有 MQ2 断线、漂移或未预热情况。
4. 用调试器注入气体样本并同步有效标志/时间戳，输入 99→100→75→50→49，再单独从未激活状态输入 2000、10000，确认迟滞和启动行为；测试期间需避免 SensorTask 覆盖注入值。不要通过释放真实可燃气体构造高浓度。
5. 电机运行中反复切换四种模式、档位及长按启停，检查 H 桥与 PWM，确认防回流退出/重入后不沿用旧激活状态；触发 OTA，确认立即停机且控制任务不能重新拉起。
6. 观察看门狗、自检转正、实际 OTA/回滚，以及 UI/电机/传感器任务栈水位。任务优先级、栈大小、引脚、Flash 分区、Bootloader 源码、OTA 协议及看门狗框架均未调整。
