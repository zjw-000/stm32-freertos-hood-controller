## 3. 首次安装：必须同时更新 Bootloader 和 APP

此次协议/元数据由 v2 改为 v3，旧软件不能混用；片内和片外分区地址保持不变。

1. 先将按键2改接 PB0，核对 Flash CS 仍为 PB12；准备原基线固件作为开发回退材料。
2. 运行 `tools/build_keil.ps1`，得到 `OBJ_BL/Bootloader.bin` 与 `OBJ/APP.bin`；也可使用相应 HEX。
3. 使用 SWD 分别烧录 Bootloader 至 `0x08000000`、APP 至 `0x08002000`。烧 APP 时禁止全片擦除后丢失 Bootloader。
4. 旧 v2 元数据会被判为不兼容。按住 KEY1（PB1）上电，在 Flash 可识别且本地 APP 向量合法时登记本地烧录固件（版本0），进入试运行；成功运行约5秒后转正。
5. 登记只适用于无有效 v3 元数据的首次部署，不会把 v2 的半完成升级状态直接迁移过来。新版本自动升级必须使用本仓库的新发送工具。
6. 可在保持 KEY1 按住的情况下、APP 完成健康观察后，执行 `python tools/program_golden.py COM3` 固化黄金镜像；已有黄金镜像时该命令拒绝覆盖。

不要用旧版上位机把新 APP 单独升级到旧 Bootloader 上。运行时的版本由认证清单记录，首次 SWD 登记为0，后续串口版本必须显式递增。

## 4. 正常升级与结果查询

```powershell
python tools/send_firmware.py COM3 OBJ/APP.bin --version 1
python tools/send_firmware.py COM3 --status
python tools/send_firmware.py COM3 --status --session 1234
python tools/sign_firmware.py OBJ/APP.bin --version 1
```

串口默认115200。发送工具会打印本次 session ID；END 的 ACK 仅代表镜像已暂存。只有重启后状态为 IDLE、confirmed=1 且运行版本正确，工具才报告成功；回滚至其他版本报告失败，查询超时报告尚未确认。

断线后先查询原 session；若下载会话已失效，重新发送并使用新的 session。尚未实现断电后的下载断点续传，重启后重新下载是明确行为。会话静默超时5秒、总时长上限60秒。

## 5. 状态与断电恢复约束

`PENDING_APPLY → 验证下载 → 验证并备份当前 APP → 保存 APPLYING → 擦写 APP → 保存 TESTING → APP 健康确认 → IDLE`。

- 备份写入、回读以及 APPLYING 元数据提交完成前，绝不擦除 APP。
- 重启看到 APPLYING 时禁止再备份运行区，按阶段继续安装；尝试次数持久化，超限进入恢复。
- 擦写整个 APP 分区，避免短新固件尾部残留旧代码影响镜像长度判断。
- ROLLBACK 先尝试上一稳定版，再尝试黄金镜像；恢复前检查源，恢复后再次认证，成功才能跳转。
- 全部恢复失败则进入 RECOVERY，保持电机关闭，留在 Bootloader。当前没有 Bootloader 串口救援，需通过 SWD 检修；不要把这一状态误称为“仍可无线/串口恢复”。
- A/B 元数据采用独立扇区、CRC 和可回绕序号；写入后回读确认。试运行确认和升级服务在不重叠的阶段分别独占元数据操作。

## 6. 看门狗、RAM 与任务栈

- Bootloader 正常阶段和 APP 看门狗标称约3秒；Bootloader 跳转前放宽至约6.5秒。
- APP 监督任务每250ms检查一次，正常业务任务新鲜度窗口1.5秒；升级时检查实际擦写/验证/接收循环进度及会话总时限。
- 单扇区忙等待上限800ms、页编程上限20ms；正常等待可让出 CPU，但不会无条件喂狗。每个完成的擦写步骤报告进度。
- FreeRTOS 堆为12KB；DMA 暂存256B、软件 RX 环1024B、协议缓存1043B，均由链接器分配，取消旧固定地址接收数组。
- 任务栈单位是32位字：Start 256（1024B）、IAP 512（2048B）、Key 192（768B）、UI 256（1024B）。其他任务按调用链保留余量。
- 新编译报告 Start 调用链约368B；IAP 处理函数约832B，另加解析器回调调用链与上下文，不能只读 `iap_task` 的直接调用深度。Bootloader 静态最大调用深度约872B、MSP预留1024B。
- 已启用故障钩子，并保留 `g_minFreeHeap`（字节）、`g_startStackFree` / `g_iapStackFree`（栈单元）供上板观察；未声称已经测到真实栈水位。

## 8. 安全边界及上板待验

默认密钥是公开开发占位值。生产构建必须定义 `IAP_PRODUCTION`，私下提供被 Git 忽略的 `Shared/iap_production_key.h`，定义32字节 `g_iapHmacKey`；工具使用 `--production --key-file`。APP 与 Bootloader 的私有密钥必须一致，不能把私钥文件提交或分发给终端使用者。

认证覆盖镜像及其大小、CRC、版本和板型。版本下限只防普通串口降级：元数据仍是 CRC 保护，外部 Flash 可被物理篡改时，版本下限不具备可信单调性；尚未配置芯片读保护或不可变信任根，不能宣称完整安全启动。物理维护按键用于授权本地首次登记及黄金镜像固化，不是远程身份认证替代品。

上板需验证：PB0改线、JEDEC识别、DHT11读取与5秒健康确认、所有模式电机行为、LCD与Flash并发、三类任务栈水位、看门狗在实际LSI频率下的余量、最大56KB升级、真实断电/复位、Flash断线/损坏与恢复失败状态。模拟Flash的时序和错误模型不等于真实芯片行为。
