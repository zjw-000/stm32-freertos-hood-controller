# 项目吃透总计划

## 项目与目标

- 项目：基于 FreeRTOS + STM32F103C8T6 的烟机控制系统。
- 最终目标：能沿源码解释系统启动、任务协作、模式切换、传感器决策、电机闭环与 IAP；能定位时序、并发和内存问题；能完成小改动并说明验证方法；能应对面试追问。

## 当前阶段

阶段 2“模式切换与共享状态”已完成静态源码核验，长期主线仍在阶段 3“传感器到风速决策”。本轮为解决局部知识割裂，先回到阶段 1 做整机事件流总图复盘，并局部推进阶段 4 的测速链和阶段 6 的调度/中断理解。

最近一次推进：已从源码重新串通“上电初始化 -> 启动调度器 -> StartTask 创建长期任务 -> 周期任务阻塞/唤醒 -> TIM4 ISR 通知 SpeedCalcTask -> 返回任务调度”的全局时间线，并区分 SysTick、TIM1、TIM2、TIM4 的职责。详见 [单次学习推进板](./单次学习推进板.md) 与 [学习后自动整理](./学习后自动整理.md)。

## 下一阶段顺序

1. 跟通 `SensorTask()` 如何采集 DHT11/MQ2 并更新 `g_systemState`。
2. 跟通 `WindSpeedTask()` 如何取得一致输入、调用 `WindSpeed_Update()` 并写回风速与 Cooking Event。
3. 建立“原始传感器值 -> 阈值/滤波 -> `windSpeedPWM` 与 `cookingEventActive`”表。
4. 只在决策输出明确后进入 PID、电机测速和 PWM 细节；IAP 继续后置。

阶段 2 遗留风险并入阶段 6：三个系统切换函数持有 `g_dataMutex`，但电机、UI 和防回流任务仍有未持锁的直接访问。静态源码可构造跨任务交错，实际触发条件与修复效果待运行验证。

## 吃透验收标准

- 能画出启动链、任务/中断关系图和核心数据流。
- 能不看文档讲清四种模式、自动模式子状态和关键阈值。
- 能解释每个周期任务为何采用该周期，以及超时或阻塞会影响什么。
- 能指出至少 3 个经源码证实的并发、内存或错误处理风险，并给出验证方案。
- 能从现象反查到任务、共享状态、驱动和中断层。
- 能完成至少一个行为改动，经过编译和实机或可替代测试验证。
- 对未上板、未测量的结论明确标注为待验证，不把静态阅读当成运行证明。
