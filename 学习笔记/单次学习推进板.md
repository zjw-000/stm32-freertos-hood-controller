## 本轮主链

```text
上电复位
  -> Hardware_Init：硬件配置；此时调度器未启动，delay_ms(500) 原地等待
  -> System_Init：初始化 g_systemState、互斥量、测速二值信号量
  -> StartTask_Create + vTaskStartScheduler：调度器开始挑选任务
  -> StartTask：临界区内创建长期任务，最后启动 TIM4，退出后自删除
  -> 周期任务工作后调用 delay_ms/vTaskDelay，主动进入阻塞态
  -> CPU 改跑当前最高优先级的就绪任务，空闲时运行 Idle
  -> SysTick 每 1 ms 给内核记账；TIM4 每 1 ms 发测速中断
  -> TIM4 ISR 给二值信号量，必要时立即切到高优先级 SpeedCalcTask
  -> SpeedCalcTask 读取 TIM2 编码器计数，计算后再次等待信号量
  -> CPU 回到当前最高优先级的就绪任务
```

## 本轮关键文件

- `USER/main.c`：上电后的三段初始化和调度器入口。
- `SYSTEM/delay/delay.c`、`FreeRTOS/include/FreeRTOSConfig.h`：调度前忙等、调度后任务延时、1 ms 内核 tick、抢占和时间片配置。
- `APP_TASK/app_tasks.h/.c`：任务优先级/周期、StartTask、SpeedCalcTask、TIM2/TIM4 ISR 和信号量同步。
- `BSP/MOTOR/motor.c`、`BSP/TIMER/timer.c`：TIM1 PWM、TIM2 编码器计数以及 `get_speed()` 的累计与滤波。

## 已完成的源码核验

1. `main()` 依次调用 `Hardware_Init()`、`System_Init()`、`StartTask_Create()`、`vTaskStartScheduler()`；调度器启动前的 `delay_ms(500)` 不会调用 `vTaskDelay()`，而是原地等待。
2. `System_Init()` 先给共享状态赋初值，再创建 `g_dataMutex` 和 `g_speedCalcSemaphore`。`StartTask` 在临界区创建长期任务，信号量就绪后才启动 TIM4，随后退出临界区并删除自己。
3. FreeRTOS 配置为抢占式、开启同优先级时间片，tick 为 1000 Hz。周期任务运行一小段后调用 `delay_ms()`，其整毫秒部分转为 `vTaskDelay()`，任务阻塞并让出 CPU。
4. 任务优先级从高到低为 IAP 7、测速 6、电机 5、按键 4、传感器/风速 3、防回流 2、UI 1。周期分别为按键 10 ms、传感器 500 ms、风速 100 ms、电机 50 ms、防回流 100 ms、UI 200 ms；测速任务等待信号量，不靠固定延时轮询。
5. SysTick 的 1 ms 是 FreeRTOS 的内核节拍；TIM1 的约 1 kHz 是硬件 PWM 周期；TIM2 在编码器模式下由外部脉冲驱动计数；TIM4 的 1 ms 是测速通知节拍。四者用途不同，即使其中三个数值恰好接近 1 ms，也不是同一只钟。
6. TIM4 ISR 清中断标志并调用 `xSemaphoreGiveFromISR()`；若这使优先级 6 的测速任务就绪，`portYIELD_FROM_ISR()` 可在退出中断时立刻切换。测速任务读出 TIM2 计数、调用 `get_speed()`，然后再次阻塞等待。
7. `get_speed(..., 50)` 首次在第 51 次有效调用形成一个样本，此后约每 50 次形成一个样本；第 10 个样本约在第 501 次有效调用时触发排序平均和一阶滤波，才更新返回的 `speed`。
8. 任务切换主要来自三类事件：当前任务延时或等待对象而阻塞；更高优先级任务变为就绪并抢占；同优先级任务在 tick 下时间片轮转。硬件中断是先暂停任务、执行短 ISR，再由内核决定返回原任务还是切到更高优先级任务。

## 结论边界与风险

- 已完成：上电、任务创建、周期阻塞、四类计时部件、TIM4 信号量唤醒和调度切换的静态源码核验。
- 未完成：未重新编译、未烧录上板，也未用 trace、GPIO 或逻辑分析仪测量真实执行时间、唤醒延迟和周期抖动。
- 通知合并：测速使用二值信号量而不是计数信号量；如果任务来不及取走，多个 TIM4 通知可能合成一个，不能据源码假定每次 1 ms 中断都对应一次实际计算。
- 优先级边界：硬件中断优先级和 FreeRTOS 任务优先级是两套不同规则；本轮只核验任务侧唤醒路径，不把二者混成同一张排名表。
- 计时边界：任务周期和测速的“约 50 ms/约 500 ms”依赖有效唤醒与调度；静态路径不等于实机硬实时保证。
