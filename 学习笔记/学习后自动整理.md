# 学习后自动整理

> 累计整理已完成阶段的知识骨架；执行证据与未验证边界见 [单次学习推进板](./单次学习推进板.md)。

## 阶段 1：启动与 RTOS 骨架

### 本质

这个项目不是在 `main()` 的 `while(1)` 里顺序执行全部功能，而是先把硬件和共享状态准备好，再由 FreeRTOS 把按键、传感器、决策、电机、显示、防回流和测速拆成独立任务。周期任务靠延时释放 CPU，测速任务靠 TIM4 中断发信号后才运行。

### 最短运行链路

```text
main
  -> Hardware_Init：初始化 PWM、电机、编码器、传感器、LCD 等硬件
  -> System_Init：设置待机初值，创建互斥量和测速信号量
  -> StartTask_Create：只创建启动任务
  -> vTaskStartScheduler：调度器接管 CPU
  -> StartTask：创建长期任务，最后启动 TIM4 并删除自己
  -> 周期任务：执行一次业务后进入 delay
  -> SpeedCalcTask：等待 TIM4 ISR 的二值信号量
```

### 核心角色分工

| 角色 | 职责 | 首轮后的状态 |
|---|---|---|
| `main()` | 完成调度前准备并启动 FreeRTOS | 调度器正常启动后不再继续 |
| `StartTask` | 集中创建长期任务并开启 TIM4 | 自删除 |
| `KeyScanTask` | 扫描按键并触发模式/档位/启停操作 | 延时 10 ms |
| `SensorTask` | 读取 DHT11 与 MQ2，更新共享状态 | 延时 500 ms |
| `WindSpeedTask` | 根据传感器数据更新风速决策 | 延时 100 ms |
| `MotorControlTask` | 按当前模式控制电机；默认待机时停机 | 延时 50 ms |
| `UIDisplayTask` | 刷新 LCD | 延时 200 ms |
| `AntiBackflowTask` | 在防回流模式下判断气体阈值 | 延时 100 ms |
| `TIM4_IRQHandler` | 每 1 ms给测速任务一个二值信号 | 必要时请求中断退出后切换任务 |
| `SpeedCalcTask` | 被唤醒后调用 `get_speed(50)` | 再次永久等待信号量 |

### 最容易混淆的点

1. `StartTask_Create()` 不会一次创建所有业务任务，它只创建 `StartTask`；真正的长期任务由调度器启动后的 `StartTask()` 创建。
2. `delay_ms()` 不是始终忙等：调度器启动前使用 SysTick 忙等，启动后整毫秒部分通过 `vTaskDelay()` 阻塞当前任务。
3. TIM4 的周期是 1 ms，不等于转速每 1 ms 更新。`get_speed(50)` 每 50 次调用形成一个样本，累计 10 个样本后才更新滤波结果。
4. FreeRTOS 数值更大的任务优先级更高；SpeedCalc 为 6，高于 Motor 的 5。IAP 虽定义为 7，但 `ifopen=0` 时不会创建。
5. “堆为 10 KiB、声明栈约 4 KiB”只说明账面上有余量。TCB、Idle/Timer 任务和信号量也占堆，而且源码未启用创建失败与栈溢出诊断。
6. 静态源码能证明设计路径和配置关系，不能证明真实硬件上的栈余量、执行时间、抖动或传感器成功率。

### 速记结论

- 先硬件、后共享状态、再启动任务，最后由调度器接管。
- 启动任务只是任务工厂，完成创建和 TIM4 启动后自删除。
- 普通业务靠周期延时调度，测速靠“TIM4 ISR -> 二值信号量 -> SpeedCalcTask”事件驱动。
- 系统默认进入待机低档且电机停止；IAP 当前被编译开关关闭。
- 当前最大启动风险不是配置值本身，而是创建失败和栈溢出都缺少运行期诊断。

## 阶段 2：模式切换与共享状态

### 本质

按键任务不负责连续控制电机，而是把物理按压翻译成对 `g_systemState` 的离散修改；电机、防回流和 UI 任务再按各自周期异步消费这些状态。`g_systemState` 是任务间的控制契约，但当前互斥量只保护部分写入函数，并没有形成完整的一致性边界。

### 最短运行链路

```text
GPIO 低电平
  -> 按键状态机：消抖并产生短按/长按/持续/释放事件
  -> KeyScanTask：映射到切模式、切档位或电机 Toggle
  -> System_*：修改模式、档位和 motorRunning
  -> MotorControl / AntiBackflow / UI：异步执行控制或显示
```

模式键形成 `待机 -> 手动 -> 自动 -> 防回流 -> 待机` 循环；档位键只在低/高档间改配置；电机 Toggle 的关闭路径回到待机，开启路径进入手动模式。

### 核心角色分工

| 角色 | 职责 |
|---|---|
| `Key_Scan()` | 将电平和持续时间变成稳定事件 |
| `KeyScanTask()` | 将两个按键的事件映射为用户命令 |
| 三个 `System_*` 函数 | 在互斥量内执行离散状态迁移，部分路径直接启停电机 |
| `MotorControlTask()` | 每 50 ms 按四种模式和自动子状态输出控制 |
| `AntiBackflowTask()` | 每 100 ms 根据阈值独立修改防回流状态并启停电机 |
| `UIDisplayTask()` | 每 200 ms 读取共享状态并刷新界面 |

### 最容易混淆的点

1. 短按事件在“未达到长按门槛后释放”时才产生；超过 1000 ms 的首次长按只触发一次 Toggle，持续事件只负责蜂鸣。
2. Key1 长按不切模式；Key2 长按才切电机。Key2 短按只改档位，不保证电机正在运行。
3. 用模式键进入手动模式仍会停机；用电机 Toggle 开机才同时设置“手动 + 运行”。模式和运行状态是两个字段，不能混为一个枚举。
4. 自动模式是 `STARTUP -> COOKING -> DELAY_OFF` 子状态机，60 s/60 s/10 s 是按任务每轮固定加 50 ms 得出的软件时间，不是独立硬件时钟。
5. 写者持有 `g_dataMutex` 不代表读者获得一致快照；未持锁的消费者仍可与状态迁移或硬件启停交错。

### 速记结论

- 按键层负责把有抖动的电平变成一次性语义事件。
- 系统操作层负责状态迁移，周期任务负责把状态持续变成硬件行为。
- 模式、档位和电机运行是三个相关但独立的状态维度。
- 自动模式还包含三阶段子状态机，其超时精度依赖 Motor 任务实际调度周期。
- 当前锁只串行化部分写者，不能证明共享状态快照和电机命令全局一致。

- 为什么从待机按模式键进入手动后仍不启动，而 Toggle 开机要强制进入手动？

## 专题复盘：一次正常运行中的整机事件流

### 一个统一画面

STM32 只有一个 CPU 舞台。FreeRTOS 的任务不是同时执行，而是各自工作一小段后进入延时或等待；调度器始终从就绪任务中挑优先级最高者上台。硬件定时器可在后台独立计数或输出，中断到来时短暂暂停当前任务，ISR 只处理紧急通知，再由内核决定返回原任务还是改跑刚被唤醒的高优先级任务。

### 启动到稳定运行

```text
上电
  -> Hardware_Init：配置外设；调度器尚未启动，500 ms 延时为忙等
  -> System_Init：初始化共享状态、互斥量、测速二值信号量
  -> 创建 StartTask 并启动 FreeRTOS
  -> StartTask 在临界区创建长期任务，最后打开 TIM4，然后自删除
  -> 各周期任务“运行 -> delay_ms/vTaskDelay 阻塞 -> 到期变为就绪”
  -> TIM4 ISR 每 1 ms 尝试通知 SpeedCalcTask
  -> SpeedCalcTask 读取 TIM2 编码器计数，计算后再次等待
```

### 四个容易混淆的计时部件

| 部件 | 谁让它前进 | 在本项目中的职责 |
|---|---|---|
| SysTick | 72 MHz 系统时钟分频 | 每 1 ms 给 FreeRTOS 记账，管理延时和调度 |
| TIM1 | 定时器内部时钟 | 约每 1 ms 自动完成一个 PWM 周期，持续驱动电机 |
| TIM2 | 编码器 A/B 相外部脉冲 | 累计电机转动脉冲，溢出时才进入 ISR |
| TIM4 | 定时器内部时钟 | 每 1 ms 进入 ISR，向测速任务发二值信号量 |

### 谁在什么时候换下谁

- 任务主动调用延时或等待信号量：自己下台，调度器选择别的就绪任务。
- 更高优先级任务变为就绪：发生抢占，高优先级任务先运行。
- 多个同优先级任务同时就绪：1 ms tick 可推动时间片轮转。
- 中断到来：先暂停任务执行 ISR；若 ISR 唤醒了更高优先级任务，则中断退出时可直接换人，否则返回原来的任务。

### 测速链的源码边界

`SpeedCalcTask` 不每 1 ms 都产出一个新 RPM。TIM4 每 1 ms 只负责尝试唤醒；`get_speed(..., 50)` 首次第 51 次有效调用才形成一个样本，之后约每 50 次一个样本，累计 10 个样本才更新滤波转速。二值信号量会合并未及时消费的重复通知，所以“约 50 ms、约 500 ms”是设计节拍，不是未经测量的实机保证。
