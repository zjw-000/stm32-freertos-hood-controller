一、 使用 Bootloader 与片内 Flash 需要哪些 STM32 外设配置？
[时钟]：使能片内 Flash 编程控制器（FPEC 时钟默认常开）与硬件 CRC 计算单元时钟（AHB 总线 RCC_AHBPeriph_CRC）。
[GPIO]：Bootloader 运行在芯片内部存储空间，无需外部特定引脚；但需保障电源供电稳定，防止擦写期间欠压掉电变砖。
[外设]：操作片内 Flash 前，必须先向 FLASH->KEYR 寄存器连续写入解除保护密钥对（0x45670123 与 0xCDEF89AB）解锁 FPEC；操作完成后立即置位 LOCK 上锁。
[中断/DMA]：在执行 IAP 最终跳转前，必须全局关闭中断（__disable_irq()）并清空所有外设中断挂起标志位；跳转后重定位中断向量表偏移量（SCB->VTOR）。
[硬件电路]：芯片内部 64KB Flash 划分分区：Bootloader 引导区（0x08000000~0x08002000，8KB）与 APP 运行区（0x08002000 起始，56KB）。
[调试验证]：在安全扇区（如 0x08003000）执行“解锁 -> 擦除 -> 半字烧写 -> 回读对比 -> 重新上锁”闭环验证，同时利用硬件 CRC32 单元对固件数据包校验校验和。
二、 高阶口述复现流程
1. 记忆抓手（锚点）
“Bootloader OTA 升级 = 解锁片内 Flash + 硬件 CRC 防篡改 + 1KB 逐页擦写 + 关中断改指针跳 APP”。

2. 口述复现链路
【1】安全校验与完整性核对：Bootloader 开机后先不启动系统，优先调用单片机内部硬件 CRC32 单元，对片外 Flash 暂存的 OTA 新固件包进行 4 字节并发校验。只要有 1 个 bit 翻转损坏，直接丢弃升级包并报错，筑牢防变砖底线。  
【2】解锁片内 Flash 控制器：单片机片内 Flash 默认处于硬件写保护状态。驱动向 FLASH->KEYR 写入两次固定密钥完成解锁，获得 FPEC 控制器的擦写授权。  
【3】按 1KB 扇区逐页擦除：因为片内 Flash 物理上只能“将 1 改写为 0”，所以单片机以 1024 字节（1KB）为单位，对 APP 目标分区（0x08002000 起始）逐页执行页擦除，将整页所有数据恢复为初始物理态 0xFFFF。  
【4】16 位半字连续烧写：擦除完成后，单片机以 16 位（半字/Half-Word） 为最小烧写单位，将固件二进制镜像连续烧入片内 Flash；烧写完毕后立即执行 FLASH_Lock() 重新锁死控制器，防止后续程序跑飞误改写代码。  
【5】环境清理与安全跳转：烧录校验 100% 正确后，执行跳转操作：先调用 __disable_irq() 彻底关闭全局中断，防止老中断干扰新系统；接着读取 APP 起始地址的栈顶指针赋给 MSP（主堆栈指针）；最后取出复位中断向量地址，强转为函数指针直接 PC 寄存器跳转执行！

3. 口述闭环金句
“Bootloader 与 OTA 的工程精髓在于‘防御性编程与干净利落的上下文交接’：通过硬件 CRC 杜绝残缺固件，遵循 Flash‘先解锁、整页擦、半字写、再上锁’的硬件法则；跳转前彻底清空外设中断并重置堆栈指针，确保 APP 在一张完全干净的物理白纸上平稳接管系统。”
