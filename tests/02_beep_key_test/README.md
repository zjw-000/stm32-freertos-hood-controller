# 02_beep_key_test 硬件自检工程使用与验证说明

## 一、 硬件物理接线（清晰引脚对应表）

本项目中，STM32F103C8T6 与**有源蜂鸣器**、**独立物理按键**以及电脑调试端接线如下：

### 1. 蜂鸣器与按键接线表
| 外设名称 | 外设引脚 | 连接 STM32F103 引脚 | 硬件物理说明与工作原理 |
| :--- | :--- | :--- | :--- |
| **蜂鸣器 (BEEP)** | I/O 控制端 | **PB15** | 推挽输出。驱动三极管基极，输出对应电平鸣叫 |
| **按键 1 (KEY1)** | 信号引脚 | **PB1** | 内部上拉输入 (IPU)。常态高电平，按键按下导通至 GND (低电平有效) |
| **按键 2 (KEY2)** | 信号引脚 | **PB12** | 内部上拉输入 (IPU)。常态高电平，按键按下导通至 GND (低电平有效) |

### 2. PC 串口观察接线（USB 转 TTL 模块）
| USB转TTL 模块引脚 | 连接 STM32F103 引脚 | 功能说明 |
| :--- | :--- | :--- |
| **TXD** (模块发送) | **PA10** (USART1_RX) | 电脑向单片机发送数据（浮空输入） |
| **RXD** (模块接收) | **PA9** (USART1_TX) | 单片机向电脑发送按键调试日志（复用推挽输出） |
| **GND** | **GND** | 必须与单片机共地 |

## 二、 软件运行过程正常验证的现象是通过什么方式观察？

**答：通过【板载物理声学反馈】与【PC 端串口调试助手】双重协同观察！**

1. **声学与物理反馈**：
   - 每次有效按下按键，板载蜂鸣器会发出清脆的“哔”声提示（短按响 80ms，长按响 300ms）。
2. **PC 端串口日志**：
   - 打开串口助手（波特率 `115200`），实时打印消抖后的按键事件与状态机变化。

## 三、 正常 vs 异常的实际输出现象对照

### 1. 正常运行的现象（声学 + 串口）
开机后，蜂鸣器先长鸣一次（100ms），串口打印引导信息：
```text
========================================
  [STM32-RangeHood] Beep & Key Test     
========================================
[Init] Beep on PB15, Key1 on PB1, Key2 on PB12.
[Ready] Press Key1 or Key2 to trigger Beep & Event...

[KEY EVENT] Key 1 SHORT Press detected! -> BEEP Short!
[KEY EVENT] Key 2 SHORT Press detected! -> BEEP Short!
[KEY EVENT] Key 1 LONG Press detected!  -> BEEP Long!
```
- **物理现象**：
  - 单击 KEY1：蜂鸣器轻响一声（80ms），串口打印 `Key 1 SHORT Press`；
  - 单击 KEY2：蜂鸣器轻响一声（80ms），串口打印 `Key 2 SHORT Press`；
  - 长按 KEY1（超过 800ms）：蜂鸣器长鸣一声（300ms），串口打印 `Key 1 LONG Press`。

### 2. 异常运行现象与排查指南
| 现象 | 故障根因分析 | 物理排查方法 |
| :--- | :--- | :--- |
| **蜂鸣器常鸣不止** | 驱动电平极性反了或三极管击穿 | 检查代码中 `Beep_on` / `Beep_off` 写入的电平逻辑；检查 PB15 外围电路。 |
| **按下按键没有任何声音和串口输出** | 按键未接通地，或引脚配置错误 | 用万用表测 PB1/PB12，常态应为 3.3V，按下应跳变为 0V。若不变，说明按键对地没接好。 |
| **按一下按键，蜂鸣器连续响很多声** | 软件去抖缺失或按键机械触点严重氧化 | 检查消抖扫描间隔是否达到 20ms 以上。 |

## 四、 落实到 Keil 源码的实现细节

1. **非阻塞状态机去抖与长按检测**：
   代码在主循环中以 20ms 为节拍调用 `Key_Scan()`，只有当连续采样为低电平时才确认按下，滤除按键机械弹片的毛刺。
2. **长按计时阈值**：
   内部计数器累计超过 40 次（`40 * 20ms = 800ms`）未松手，立即触发 `LONG_PRESS` 事件。
3. **事件显式消费机制**：
   触发事件后必须显式调用 `Key_ClearEvent()`，防止同一按键动作在单片机循环中被重复消费。
