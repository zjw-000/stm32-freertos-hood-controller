# W25Q64 核心开发知识点（面试口述版，精简要点，适合嵌入式面试）

> 
> W25Q64：SPI Flash，容量 **64Mbit = 8MB**；标准 SPI，支持双线 Dual SPI、四线 QPI。
> 页：**256 字节 / 页**；扇区：**4KB**；块：32KB/64KB；整片 8MB。
> 重点记住：**只能把 1 写成 0，擦除才能把 0 变回 1；擦除最小单位是扇区，不能只擦单个字节**。

## 1. 容量与地址

- 64Mbit，除以 8 → **8MB，地址范围：0x000000 ~ 0x7FFFFF**
- 扇区 Sector：4KB（0x1000），**擦除最小单位**，平时项目最常用扇区擦除
- 块 Block：64KB（0x10000），大块擦除速度更快，但一次性擦除范围大，风险高
- 页 Page：256 字节（0x100），**写的最小单位**。写操作只能一页一页写，写的时候地址不能跨页，跨页会从页首覆盖，这是踩坑高频点。

> 
> 一句话记忆：**读：按任意字节读；写：按页写；擦除：按扇区擦**

## 2. SPI 通信基础（STM32 驱动）

- 标准 SPI 模式：**模式 0 CPOL=0，CPHA=0**（大部分 W25Q 默认）
- 引脚：
  - SCK：时钟
  - MOSI：主机发 → Flash 收
  - MISO：Flash 发 → 主机收
  - CS：片选，**拉低选中，拉高结束传输**
  - WP：写保护；HOLD：暂停（很多项目直接把 WP/HOLD 上拉，不使用）

> 
> 注意：SPI 是**先传高位 MSB 先行**，这个和 STM32 SPI 配置选项对应，配置错就读不出 ID。

## 3. 常用指令（面试必背，挑重点）

- 0x90 / 0x9F：读 JEDEC ID。W25Q64 的 ID：`0xEF 0x40 0x17`。**驱动第一步就是读 ID，用来校验硬件有没有接上 Flash**。
- 0x03：普通读，低速，任意地址读
- 0x0B：快速读，需要多传一个 dummy 空字节，速度更高
- 0x02：页编程（page program，写数据），最多写 256 字节一页
- 0x20：扇区擦除（4KB）【项目最常用】
- 0xD8：块擦除（64KB）
- 0xC7：整片擦除，很慢，一般产品代码禁止用，调试偶尔用
- 0x06：写使能 WREN ✅【非常重要！】

> 
> ⚠️ 重点坑点：**任何写 / 擦除操作之前，必须先发 0x06 打开写使能，不然操作无效！**
> 0x05：读状态寄存器 SR（bit0 = BUSY 位）
> 每次发起擦除 / 页写之后，要循环读状态寄存器，等待 BUSY 位变 0，代表操作完成。**擦除是硬件耗时操作，不是发完指令立刻完成**。

## 4. 存储特性（面试高频提问）

1. Flash 存储单元：默认擦除后是`0xFF`；写操作只能把 bit 从 1→0，**不能 0→1**。想把 0 变回 1，只能执行擦除。

> 
> 举例子：原来数据是 0xFF，写 0x11 没问题；如果已经写了 0x00，想直接改成 0xFF 不行，必须先擦扇区。

2. 寿命：典型 **10 万次擦写 / 扇区**。读操作不限次数，读不损耗寿命。
3. 掉电：非易失，断电数据保留。
4. 擦写时间：扇区擦除大概几十 ms，页写几百 us。**不能阻塞死等太久，如果在 FreeRTOS 里，不能 while 死循环，最好用信号量 + 轮询，或者让出任务**。

## 5. 工程上的典型用途（和你 IAP 双区升级关联！面试加分）

> 
> 刚好可以接上你前面 IAP 升级的话题：
> 很多产品，STM32 内置 Flash 空间不够存两份 APP 固件做双区，就把**备用固件存 W25Q64**。
> 流程：收到升级包，分片写入 W25Q，全部写完之后，校验 CRC；校验通过，Bootloader 运行的时候，把 W25Q 里的新固件搬运复制到 STM32 内部 Flash 的 APP 分区。校验失败就不搬运，不覆盖老固件，实现防砖。
> ⚠️ 坑：W25Q 只是外部 SPI 存储，**不能直接在上面跑程序**，不能直接映射成执行内存，必须拷贝到 STM32 内部 Flash 才可以运行代码。（这点面试官很爱问！很多人误以为可以直接在 SPI Flash 跑代码，除非用 XIP 芯片，W25Q 不是 XIP）

## 6. 高频踩坑清单（面试可以主动提，体现工程经验）

1. 忘记发 WREN (0x06) 写使能，擦写完全没效果。
2. 页写跨页：起始地址 + 写入字节超过 256，数据会折回页开头覆盖。解决方案：写之前判断页边界，分页写入。
3. 不等待 BUSY 标志，擦除还没完成就继续发下一条指令，数据错乱。
4. SPI 时序错：CPOL/CPHA、MSB/LSB 配置错误，读出来的 ID 乱码。
5. 频繁擦同一个扇区：比如直接用扇区存实时计数值，会快速耗尽擦写寿命；这种场景要用磨损均衡（wear leveling）。
6. 掉电风险：擦写中途断电，扇区数据损坏；升级场景要做断点续传 + CRC 校验，不要一边写一边覆盖旧固件。

## 7. 可选：CRC 校验

一般升级场景：固件写到 W25Q 之后，计算整个固件区域的 CRC32，把 CRC 值单独存在 W25Q 的固定位置。Bootloader 拷贝之前，重新算一遍 CRC 比对，确认固件完整，再拷贝进片内 Flash。

### 简短口述总结（直接背，被问到 W25Q 的时候，一句话开场）

> 
> W25Q64 是 8MB 的 SPI Nor Flash，标准 SPI0 模式。最小读单位是字节，写是 256 字节一页，擦除最小是 4KB 扇区。擦写前必须开启写使能，操作后查询 BUSY 位等待完成。擦写会消耗寿命，读不损耗。在我们 IAP 项目里，我用它来存放备份固件；它不能直接执行代码，需要 Bootloader 把固件拷贝进 STM32 内置 Flash 再跳转。开发要注意页边界，还有掉电保护、CRC 完整性校验，防止升级失败变砖。



一、 使用 W25Q64 需要哪些 STM32 外设配置？
[时钟]：使能 GPIOA、GPIOB（APB2 总线）以及 SPI1 硬件外设时钟（APB2 总线）。
[GPIO]：配置 PA5（SCK）、PA7（MOSI）为复用推挽输出（GPIO_Mode_AF_PP），PA6（MISO）为浮空/上拉输入（GPIO_Mode_IN_FLOATING）；配置 PB12（片选 CS）为通用推挽输出（GPIO_Mode_Out_PP）。
[外设]：配置 SPI1 为双线全双工主机模式、8 位数据帧、时钟空闲为高且偶数沿采样（CPOL=1, CPHA=1，Mode 3）、软件片选 NSS、波特率预分频设为 2 分频（最高 36MHz 传输速率）。
[中断/DMA]：测试工程采用 SPI 查询发送与接收缓冲器标志位（TXE / RXNE），未使能中断与 DMA（项目高阶版可配置 DMA 完成固件整块搬运）。
[硬件电路]：芯片为 Winbond W25Q64（容量 8MB / 64Mbit），支持标准 SPI 接口，VCC 供电 3.3V，CS 引脚建议外部并联 10kΩ 上拉电阻至 3.3V 确保上电防误写。
[调试验证]：示波器量取 SPI 通信波形，或通过读取厂商 JEDEC ID（Winbond 标准识别码：0xEF4017）验证硬件总线电气连通性，并通过写/读/校验测试闭环功能。
二、 高阶口述复现流程
1. 记忆抓手（锚点）
“W25Q64 存储驱动 = 读写前先使能 + 写前必先整扇区擦除 + 页写入跨界限制 + 忙状态轮询等待”。

2. 口述复现链路
【1】总线心跳与 ID 校验：单片机拉低 PB12（CS），通过 SPI1 发送读 ID 指令并接收返回数据。若读出厂商码 0xEF 和容量标识码 0x4017，证明 SPI 四根信号线电气连接完全正常，芯片已处于就绪状态。  
【2】写使能授权：无论是擦除还是写入，操作前单片机必须先发送“写使能（Write Enable）”指令，拉低片选再拉高，将芯片状态寄存器中的 WEL 写使能锁位置 1，否则任何写操作都会被芯片硬件直接丢弃。  
【3】写前必须先擦除（逢写必擦）：Flash 物理层只能将比特位“由 1 写成 0”，无法直接“由 0 改写为 1”。因此写入新数据前，必须先下发“扇区擦除”指令（4KB 扇区为最小擦除单位），将目标区域所有字节恢复为物理全 0xFF。  
【4】页编程限制（单次最多 256 字节）：写入数据时，单片机发送“页编程（Page Program）”指令与目标地址，连续灌入数据。单次连续写入不能超过 256 字节（1 页大小），且严禁跨越页物理边界，若数据超过一页，驱动必须在软件层按 256 字节拆包分次写入。  
【5】硬件忙状态轮询（BUSY 位）：擦除和页编程需要几十毫秒的内部物理电荷迁移时间。单片机下发写指令后，需持续循环读取状态寄存器 1，直到判断 BUSY 标志位归 0，确认芯片内部物理写入彻底完成，方可进行下一次操作或读取校验。

3. 口述闭环金句
“W25Q64 存储驱动的核心在于顺应 Flash 的物理特性：牢记‘写前必使能、写入必先擦、单页限 256、写完等 BUSY’这十六字箴言；在系统设计中通常作为 OTA 升级的固件镜像缓存区和离线大容量配置区，极好地弥补了单片机片内 Flash 空间的不足。”
