# 03_usart_test 串口通信（USB 转 TTL）独立测试工程

## 一、这个工程干什么用

专门用来**验证"STM32 ↔ USB 转 TTL 模块 ↔ 电脑串口助手"**这条链路是否通畅。
不依赖按键、蜂鸣器、传感器，只测串口，排除一切干扰，最适合用来判断：
- 你的 **USB 转 TTL 模块本身好不好**（CH340/CP2102 等）；
- 接线对不对（TX/RX 有没有接反）；
- 波特率、数据格式设对没有。

芯片：**STM32F103C8T6** ｜ 串口：**USART1** ｜ 波特率：**115200, 8-N-1**

---

## 二、硬件接线（关键，别接反）

| USB 转 TTL 模块 | 接到 STM32F103 | 说明 |
| :--- | :--- | :--- |
| **TXD** | **PA10** (USART1_RX) | 模块发 → 单片机收 |
| **RXD** | **PA9** (USART1_TX) | 单片机发 → 模块收 |
| **GND** | **GND** | 必须共地，否则乱码/收不到 |
| VCC / 3.3V | 可不接 | 板子用 ST-Link 的 3V3 供电即可 |

> ⚠️ 最容易犯的错：**TXD 和 RXD 接反了**。记住口诀"**交叉对接**"——模块的 TX 接单片机的 RX，模块的 RX 接单片机的 TX。

> ⚠️ **ST-Link 的 USB 口不能当串口用**（独立 ST-Link V2 没有虚拟串口）。看串口日志必须用这个独立的 USB 转 TTL 模块，ST-Link 只负责烧录和供电。

## 四、验证方法（两步走，看现象）

### 现象 1：开机引导 + 心跳（测"单片机 → 电脑"方向）
烧录复位后，串口助手应立即收到：

```
========================================
  [STM32-RangeHood] 03_USART_TEST
  USART1 : 115200, 8-N-1
  PA9=TX , PA10=RX
========================================
[Ready] Auto heartbeat: 1 line/s; any byte you send will be echoed back.
[Heartbeat] alive #1
[Heartbeat] alive #2
[Heartbeat] alive #3
...
```
> **每秒收到一行 `[Heartbeat] alive #N`** → 单片机的**发送链路**通，说明 TX(PA9)→模块RXD 这条线对了。

### 现象 2：回显 Echo（测"电脑 → 单片机 → 电脑"双向往返）
在串口助手的**发送框**输入任意内容（如 `hello` / `123`）点"发送"，MCU 会把收到的每个字节**原样回发**，串口助手的接收区就会显示你刚发的 `hello`。

> **发什么就回什么** → 接收链路 + 双向都通，整条串口通路完全正常。

## 五、故障排查表

| 现象 | 可能原因 | 处理 |
| :--- | :--- | :--- |
| 串口助手**一个字都收不到** | TX/RX 接反、GND 没接、COM 口选错、波特率不是 115200 | 交叉对调 TX/RX；补 GND；重新扫端口 |
| 收到**全是乱码**（满屏问号/方块） | 波特率不匹配、晶振/时钟不对 | 两边都设 115200，确认芯片跑 72MHz |
| **只收到心跳，发消息无回显** | 发送端RX线没接好（模块RXD→PA9 断了） | 检查模块 RXD → STM32 PA9 |
| **能回显但无心跳** | 心跳靠 delay 计时，若串口正常则不可能；多半是误判 | 重启串口助手再看 |
| 烧录报 `No ST-LINK detected` | ST-Link USB 驱动未装（与串口无关） | 见 memory 中 `keil_stlink_flash_diag_sop` |

## 六、额外：顺手验证 USB 转 TTL 模块好坏（不用单片机）

想知道**模块本身**有没有坏，最快的方法：

1. 把 USB 转 TTL 模块的 **TXD 和 RXD 两个引脚用杜邦线直接短接**（自环）；
2. 打开串口助手选中该 COM 口；
3. 发送任意内容 —— **如果接收区立刻原样显示你发的内容**，说明模块收发都正常；
4. 如果自环都没回显，那就是**模块或驱动坏了**，先换模块/重装驱动，别再折腾 STM32。
